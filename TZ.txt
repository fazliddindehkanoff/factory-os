2. КОНТЕКСТ ПРОДУКТА
====================

Factory OS — это универсальная AI-powered operating system для заводов, производств, складов, снабжения, документов, финансов, согласований и Telegram-процессов.

Первый target — Zelal Textile, но система должна быть универсальной и масштабируемой на другие заводы, фабрики, холдинги и procurement-heavy businesses.

Главная философия:

One request.
One dashboard.
One lifecycle.
One DNA log.
One source of truth.

Главный lifecycle:

Need appears
→ Request created
→ Warehouse check
→ Stock available?
→ Reserve stock OR procurement
→ Supplier search
→ Quotation comparison
→ Budget check
→ Approval chain
→ Contract / document check
→ Invoice received
→ Finance review
→ Payment approval
→ Paid / partially paid
→ Delivery
→ Warehouse receiving
→ Issue to department
→ Request closed
→ DNA log + AI learning + reports

Проверь, поддерживает ли проект эту цепочку реально, а не только визуально.

Не считай UI готовым, если это просто статичная карточка без реального API/action.

Не считай workflow готовым, если нет status history, permission check, audit/DNA log и notification.

============================================================
33. ОСОБЫЙ ФОКУС ДЛЯ БУНЁДА, САРВАРА И МАТИАСА
==============================================

Нам нужно понять:

1. Что реально сделал разработчик?
2. Что он сделал правильно?
3. Что он сделал неправильно?
4. Что он не сделал?
5. Где frontend обманывает, показывая неработающие функции?
6. Где backend не защищает действия?
7. Где роли нарушены?
8. Где Mini App не готов?
9. Где Factory OS не готов как система?
10. Что нужно дать разработчику как конкретные задачи дальше?

Поэтому финальный отчет должен быть пригоден для передачи разработчику как task list.

Каждая задача должна иметь:

* title;
* priority;
* module;
* file/path;
* problem;
* expected result;
* suggested implementation direction;
* acceptance criteria.

34. ACCEPTANCE CRITERIA ДЛЯ ТВОЕГО АУДИТА
=========================================

Твой аудит будет считаться хорошим, только если:

* проверены все основные экраны;
* проверены все основные кнопки/actions;
* проверены все формы/поля;
* проверены все роли;
* проверены все critical workflows;
* найденные баги имеют конкретные файлы/пути;
* есть readiness percentages;
* есть P0/P1/P2/P3 classification;
* есть clear Go/No-Go;
* есть конкретный roadmap;
* отчет можно сразу отправить разработчику.

Начинай аудит с чтения требований и структуры проекта.
Не меняй код.
Верни только отчет.
