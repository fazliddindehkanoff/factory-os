# Factory OS — Procurement Smoke Checklist

Ручная проверка Procurement Lite в Mini App (dev/staging). Нужен workflow с шагами `warehouse_check → procurement → …` (стандартная цепочка `seed:pilot`-холдинга такой шаг содержит) и пользователи с ролями `warehouse` и `procurement_head`/`procurement_manager`.

## Сценарий

1. Войти ролью со `warehouse.check_stock`; на шаге **Проверка склада** нажать **«Нет в наличии»** → заявка уходит в закупку (статус `procurement`).
2. Войти ролью `procurement_head` / `procurement_manager`.
3. Открыть вкладку **«Закупки» → Очередь** — заявка видна.
4. **Поставщики** → создать поставщика (если справочник пуст), задать название/ИНН/телефон.
5. Открыть заявку → **Добавить КП** → выбрать поставщика из dropdown, ввести сумму → сохранить. Заявка остаётся в закупке.
6. (Опц.) добавить второе КП от другого поставщика.
7. **Выбрать поставщика** → выбрать КП:
   - если КП **одно** — появляется предупреждение «Только одно КП по заявке…», выбор **не** блокируется;
8. После выбора workflow продвигается на следующий шаг; у заявки виден выбранный поставщик (✓ выбран).

## Проверки доступа

- **requester / warehouse / observer / auditor** (нет `procurement.view`) — вкладку «Закупки» **не видят**.
- Кнопки **Добавить КП / Выбрать поставщика** на детали приходят с backend (`availableActions`) — у непрофильных ролей их нет.
- Создание/архив поставщиков — только при `suppliers.manage`; backend в любом случае вернёт 403 при попытке в обход UI.

## Гейт
- `web build` зелёный.
- Пилотный golden path (`seed:pilot`) не сломан.
