# Factory OS — Pilot Smoke Checklist

Ручная проверка золотого сценария на детерминированных демо-данных (`npm run seed:pilot`).
Запускать в **dev/staging** окружении — НЕ на проде (использует dev-вход).

> ⚠️ **`seed:pilot` НИКОГДА не запускать против production / общей prod-БД** — он добавит демо-холдинг и демо-юзеров в боевые данные. Под `NODE_ENV=production` команда откажется (обход только `FORCE_DEMO_SEED=1`). Для демо используйте отдельную local/dev/staging БД.

## Подготовка

1. В `.env`: `NODE_ENV=development`, `ENABLE_DEV_AUTH=1` (dev-вход по Telegram id; на проде запрещён и приложение с ним не стартует).
2. `npm install`
3. `npm run db:migrate`
4. `npm run seed:pilot`
5. `npm run dev` (бэкенд) и в отдельном терминале `cd web && npm run dev` (Mini App).

Демо-пользователи (вход по Telegram id через dev-вход). PIN = **1234**:

| Telegram id      | Роль       | PIN  |
|------------------|------------|------|
| `pilot_requester`| Заявитель  | —    |
| `pilot_director` | Директор   | 1234 |
| `pilot_warehouse`| Склад      | 1234 |
| `pilot_admin`    | Админ      | —    |

Материалы: «Подшипник 6205» = 100, «Ремень приводной A-100» = 1.

## Золотой сценарий (успех)

1. Войти как **pilot_requester**.
2. Создать заявку на «Подшипник 6205», количество 5.
3. Проверить: заявка появилась в списке, статус «На согласовании», есть номер.
4. Войти как **pilot_director**.
5. Открыть заявку → «Согласовать» → ввести PIN `1234`.
6. Проверить: статус «Проверка склада».
7. Войти как **pilot_warehouse**.
8. Открыть заявку → «В наличии» (warehouse_check).
9. Проверить: статус «Выдача»; в таймлайне подсказка «→ Склад должен выдать материал».
10. Нажать «Выдать в отдел» (issue).
11. Проверить: статус «Подтверждение получения».
12. Войти как **pilot_requester** → «Подтвердить получение» → статус «Закрыта».
13. Проверить остаток: «Подшипник 6205» = **95** (списан ровно один раз).
14. Проверить историю/таймлайн: согласование → проверка склада → выдача → закрытие.

## Сценарий нехватки (fail-loud)

15. Как **pilot_requester** создать заявку на «Ремень приводной A-100», количество 5.
16. Директор согласует (PIN `1234`), склад отмечает «В наличии».
17. Склад нажимает «Выдать» → должна вернуться ошибка **«Недостаточно остатка на складе»**.
18. Проверить: заявка осталась на шаге «Выдача» (не закрылась), остаток «Ремень» = **1** (не изменился), движение склада **не** создано.

## Критерий приёмки

Новый человек проходит оба сценария по этому чеклисту **без знания внутреннего кода**.
